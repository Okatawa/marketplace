# Руководство по проекту «Рядом»

«Рядом» — небольшой сайт объявлений. Он нужен, чтобы на работающем примере разобраться, как несколько Go-программ образуют одно приложение: где они хранят данные, как передают друг другу изменения и что происходит при сбоях.

Это руководство можно читать без предварительного знания Kafka или Kubernetes. Знание основ Go пригодится в разделе про код. Термины объясняются по ходу текста; короткие определения собраны в [словаре](guide/glossary.md).

## Если вы открыли проект впервые

Пройдите первые три пункта по порядку. Остальное можно выбирать по интересу.

1. [Первый запуск](guide/getting-started.md). Какие программы нужны, где вводить команды, как открыть сайт и понять, что он работает.
2. [Пользовательский сценарий](guide/user-guide.md). Выставить вещь на продажу, найти её под другим аккаунтом, написать продавцу и прочитать письмо.
3. [Как устроено приложение](architecture/overview.md). Почему здесь шесть сервисов, пять баз и Kafka; как изменение объявления попадает в поиск.
4. [Путеводитель по коду](guide/code-tour.md). В каком порядке открывать файлы и как проследить один запрос от браузера до базы.
5. [Работа с API вручную](guide/api-walkthrough.md). Повторить основные действия из терминала и увидеть данные, которыми обмениваются браузер и сервер.
6. [Проверки и тесты](guide/testing.md). Что проверяет каждая команда и какие зависимости ей нужны.
7. [Упражнения со сбоями](exercises/failures.md). Посмотреть, как система догоняет пропущенные изменения после восстановления Kafka или Search.

Не нужно сразу поднимать Kubernetes. Для знакомства достаточно Docker Compose: он запускает все части приложения на одном компьютере.

## Как читать команды

Если раздел не говорит иначе, команды выполняются в терминале **из корня репозитория** — папки, где находятся `README.md`, `Makefile`, `go.mod` и `compose.yaml`.

Команды в блоках можно копировать без символа приглашения терминала: он специально не добавлен. Строка с `#` — пояснение, её не обязательно вводить. Команды рассчитаны на Bash или Zsh. Windows требует подходящего Linux-окружения, например WSL; отдельный запуск в PowerShell здесь не проверялся.

Пример:

```sh
make logs
```

Это значит «запустить готовую команду `logs` из Makefile». Она показывает новые сообщения сервисов и продолжает работать. Для выхода нажмите `Ctrl+C`; приложение при этом останется запущенным.

В примерах API переменные вроде `listing_id` содержат значения из предыдущего ответа. Выполняйте такие шаги в одном терминале и по порядку. Если открыть новое окно терминала, эти переменные в нём не появятся сами.

Внешний адрес `http://127.0.0.1:8080` означает «этот компьютер, порт 8080». Он доступен браузеру на вашем компьютере. Имя `http://listings:8080` используется **внутри** контейнерной сети; открывать его в обычном браузере не нужно.

## Где правда о поведении приложения

Руководства описывают текущую реализацию. Точные поля HTTP-запросов перечислены в [OpenAPI](../api/openapi.yaml), форматы событий — в [JSON Schema](../api/events/). Примеры проверок находятся в [tests](../tests/).

В `docs/superpowers/` сохранены исходные [требования](superpowers/specs/2026-10-19-marketplace-design.md) и [план разработки](superpowers/plans/2026-10-19-marketplace.md). Это история решений, а не обязательный маршрут для первого знакомства. Часть первоначальных имён файлов и разбивки задач была уточнена во время разработки.

## Где заканчиваются возможности примера

Здесь можно изучить регистрацию, объявления, фотографии, поиск, переписку, события, повторные попытки и развёртывание. Здесь нет платежей, доставки, модерации и восстановления забытого пароля.

Локальный стенд намеренно небольшой: один PostgreSQL, один брокер Kafka, один S3-сервер. Запуск приложения в контейнерах ещё не означает, что оно готово обслуживать реальных пользователей. Ограничения и непроверенные условия перечислены в [архитектуре](architecture/overview.md) и [отчёте проверок](verification.md).
