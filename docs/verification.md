# Проверка стенда

[К оглавлению](README.md)

Проверки выполнены 20 октября 2026 года на macOS arm64, Go 1.27.1, Docker Engine 29.8.2. Это проверка учебного стенда, не нагрузочная аттестация.

Интеграционные тесты работают с настоящими PostgreSQL, Kafka и S3, создавая отдельные схемы и временные топики. Они проверяют права владельца и участника, одноразовый refresh, конфликт версии, идемпотентность сообщений, старые версии событий, DLQ, отмену обработки без commit, восстановление аренды email-задания и границу SMTP/PostgreSQL.

Тест outbox намеренно ломает обновление `sent_at` после приёма события Kafka: повтор имеет прежний `event_id`. Тест SMTP намеренно ломает запись результата после отправки: два вызова отправки при одном задании показывают документированную возможность повторного письма.

Проверки переиндексации включают конкурирующее снятие объявления, ошибку экспорта и некорректное новое событие. При неуспехе активная проекция сохраняется. Дополнительно проверены 30 вариантов неполного или некорректного snapshot: они возвращают постоянную ошибку для DLQ и не заменяют действующую запись; нулевая цена допустима.

Финальное независимое ревью выявило и помогло исправить потерю следующего черновика чата, неполные snapshot поиска, отсутствие `request_id` в ошибках middleware и ожидание старых неудачных migration Jobs. Формат ошибок 401/404/405/429/502 проверен HTTP-тестом; цели ожидания миграций сопоставлены с именами реально отрендеренных Jobs.

## Учебное восстановление баз — 20 октября 2026

Шесть приложений были временно остановлены, чтобы данные не менялись между снимками. Для Accounts, Listings, Search, Messaging и Notifications сделаны дампы `pg_dump -Fc`. После этого исходные приложения запущены обратно.

Копии восстановлены через `pg_restore --exit-on-error --no-owner --no-privileges` в отдельном контейнере PostgreSQL 17.6 без сети и опубликованных портов. Для каждой базы заранее созданы её роль и пустая база. Проверка сравнила SHA-256 упорядоченных строк всех 19 таблиц и состояние последовательностей — счётчиков, используемых при выдаче новых номеров. Все значения совпали. Временный контейнер после проверки удалён; исходные базы при восстановлении не изменялись.

Дампы и технический отчёт находятся в игнорируемом каталоге `.local/backups/restore-check-20261020-232203/`. Эти файлы содержат учебные данные и не добавляются в Git. Проверка подтверждает восстановление **PostgreSQL**, но не всего приложения из резервной копии: S3-фотографии, Kafka и согласование их состояния с базами в этом упражнении не восстанавливались.

## Проверка документации — 21 октября 2026

Из [практикума API](guide/api-walkthrough.md) извлечены все десять блоков `sh` и выполнены одним Bash-процессом без изменения команд. Сценарий завершился успешно: созданы два учебных аккаунта, черновик с PNG и диалог; проверены публикация и исчезновение из поиска, повтор сообщения без дубля, ошибки прав и версии, обновление сессии и выход. Доставка письма этим практикумом автоматически не проверяется — для неё есть отдельный smoke-тест.

Команды создают новые учебные данные. В конце объявление снято с продажи, сессии закрыты, временные файлы с токенами удалены. Само объявление и переписка остаются в стенде. Локальный журнал проверки: `.local/docs-api-walkthrough.log`.

Проверены существование локальных Markdown-ссылок и синтаксис всех блоков `sh`/`bash` в пользовательской документации. Это проверка ссылок и синтаксиса, а не запуск всех административных команд. Отдельно дословно выполнен блок восстановления из [инструкции резервного копирования](runbooks/deployment-and-backups.md) на пяти ранее созданных дампах: `pg_restore` завершился успешно для каждой базы. Временный контейнер удалён. Локальный журнал: `.local/docs-restore-check.log`. Внешний Kubernetes и разрушительные команды очистки в ходе проверки документации не запускались.

## Окружение и воспроизводимость

### Исправление Grafana — 24 октября 2026

При запущенных контейнерах и доступных метриках Prometheus панели Grafana возвращали `Plugin not registered`: запрос `/api/ds/query` завершался HTTP 404. Проверка доступности Grafana и сбора метрик этого не обнаруживала. В логах было видно, что при фоновом обновлении выгружался встроенный плагин Prometheus.

В Compose отключено автообновление предустановленных плагинов, контейнер Grafana пересоздан. Новая команда `make observability-check` воспроизвела ошибку до исправления и прошла после него: запросы всех шести панелей успешны, через Grafana получены числовые значения outbox. После обновления страницы в браузере появились HTTP-графики. Остальные контейнеры наблюдаемости — Collector, Jaeger и Prometheus — также запущены. Эта проверка не заменяет проверку доставки трассировок или нагрузочный тест.

## Что этой проверкой не подтверждено

- GitHub Actions ещё не запускался на удалённом репозитории; подготовлен workflow с зафиксированными SHA actions.
- Не проводились нагрузочные тесты, аудит для публичной эксплуатации, облачное развёртывание и полное восстановление всего стенда (БД + S3 + Kafka). Локальное восстановление пяти PostgreSQL-дампов проверено отдельно выше.
- NetworkPolicy проверена по схеме; стандартный kindnet не обеспечивает её исполнение. Для проверки сетевой изоляции нужен соответствующий CNI.
- Не проверена отказоустойчивость при потере узла: локальные зависимости одноузловые.
- SMTP обеспечивает повторные попытки, но не exactly-once доставку.

Практические эксплуатационные ограничения и упрощения перечислены в [архитектуре](architecture/overview.md). Исходный план содержит более мелкую разбивку проверок; в реализации связанные случаи объединены в сценарные тесты. Наличие тестов не означает исчерпывающую проверку всех сочетаний входных данных.
