# Первый запуск

[К оглавлению](../README.md) · Далее: [пользовательский сценарий](user-guide.md)

Цель этой инструкции — получить работающий сайт с несколькими объявлениями. Разбираться в устройстве Kafka и Kubernetes для этого не требуется.

## 1. Подготовьте инструменты

| Инструмент | Для чего он нужен здесь |
|---|---|
| Docker Engine и Docker Compose | Запускают приложение, базы данных и другие зависимости в контейнерах |
| Go 1.27.1 | Выполняет подготовку локальных настроек, создание демоданных и Go-тесты; версия соответствует текущему Dockerfile |
| Make | Даёт короткие команды вроде `make up`, чтобы не вводить длинную последовательность вручную |
| Браузер | Открывает сайт |

Контейнер — отдельное окружение с программой и её зависимостями. Образ — заготовка, из которой Docker создаёт контейнер. Например, из образа PostgreSQL запускается контейнер с базой данных.

Node.js/npm нужны только для браузерных тестов и части проверок документации API. `kubectl`, Helm и kind понадобятся позднее для Kubernetes. Чтобы просто открыть сайт, эти инструменты не нужны.

Откройте терминал и проверьте:

```sh
go version
make --version
docker version
docker compose version
```

У `docker version` должны быть сведения о клиенте **и сервере**. Если есть только клиент и сообщение о невозможности соединиться, Docker Engine ещё не работает. На компьютере с Docker Desktop откройте Docker Desktop и дождитесь готовности движка, затем повторите проверку.

Команда `not found` означает, что программа не установлена или терминал не видит путь к ней. Сначала исправьте это, затем переходите к запуску проекта.

Ориентир для Docker — 8 ГБ памяти и 4 CPU. Это запас для учебного стенда, а не измеренный минимум. Одновременные Compose, наблюдаемость и Kubernetes используют больше ресурсов. На первом запуске потребуется интернет для скачивания образов и библиотек.

## 2. Перейдите в папку проекта

Откройте терминал в папке `go_example_app`. Если переходите командой `cd`, укажите путь, по которому проект находится **у вас**. Проверить текущую папку можно так:

```sh
pwd
ls README.md Makefile go.mod compose.yaml
```

Вторая команда должна найти все четыре файла. Если нет, вы находитесь не в корне проекта.

Все последующие команды выполняются из этой папки.

## 3. Запустите приложение

```sh
make up
```

Команда делает несколько вещей:

1. Создаёт файл `.local/.env` со случайными локальными паролями и ключами. Если он уже существует, сохраняет имеющиеся значения.
2. Собирает Go-программы в Docker-образы.
3. Запускает PostgreSQL, Kafka, хранилище фотографий и локальную почту.
4. Создаёт нужные таблицы в базах. Этот шаг называется **миграцией**.
5. Запускает шесть сервисов приложения и ждёт их готовности.

Первый запуск дольше последующих: скачиваются образы и библиотеки. Ориентируйтесь на успешное завершение команды, а не на фиксированное число минут.

Проверьте контейнеры:

```sh
docker compose --env-file .local/.env ps
```

У `gateway`, `accounts`, `listings`, `search`, `messaging`, `notifications` ожидается состояние `Up` и отметка `healthy`. Это значит, что встроенная проверка готовности отвечает успешно. Проверка готовности не заменяет проверку всех действий на сайте.

Контейнеры `migrate` и `kafka-init` выполняют разовую работу и завершаются. Успешное завершение с кодом `0` для них нормально; постоянно работать они не должны. Посмотреть и завершённые контейнеры:

```sh
docker compose --env-file .local/.env ps -a
```

Не копируйте `.env.example` поверх `.local/.env`: пример показывает названия настроек, а реальные значения генерирует `make setup`. Папка `.local/` исключена из Git. Не отправляйте её содержимое в публичный репозиторий.

## 4. Добавьте демонстрационные данные

```sh
make seed
```

Команда создаёт Анну и Бориса, а затем восемь объявлений Анны с иллюстрациями. Она обращается к работающему приложению через HTTP, поэтому сначала должен закончиться `make up`.

Повторный запуск не создаёт заново демообъявления с уже существующими названиями. При этом `seed` не является командой сброса: он не удаляет ваши объявления и не возвращает отредактированные демообъявления в исходное состояние.

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080). Должен появиться каталог. Если объявления ещё не видны, подождите немного и обновите страницу: поиск получает изменения отдельно от сохранения объявления.

## 5. Войдите в приложение

| Кто | Email |
|---|---|
| Анна — продавец демовещей | `anna@example.com` |
| Борис — второй участник для переписки | `boris@example.com` |

Откройте файл `.local/.env` в редакторе и найдите строку `DEMO_PASSWORD=...`. Значение после знака `=` — общий пароль этих двух учебных аккаунтов. Пароль случайный, поэтому готового универсального пароля в инструкции нет.

В браузере нажмите **«Войти»**, введите email и пароль. После входа в меню появятся имя пользователя, «Мои объявления» и «Сообщения».

Можно создать свой учебный аккаунт через **«Войти» → «Создать аккаунт»**. Подтверждение email не предусмотрено. Все письма локального стенда перехватывает Mailpit, поэтому они не уходят на настоящий почтовый адрес.

Всегда открывайте сайт через `127.0.0.1`, как в инструкции. Не переключайтесь между `localhost` и `127.0.0.1` в середине работы: браузер считает их разными адресами, а приложение проверяет адрес источника при обновлении сессии и выходе.

## 6. Проверьте основные действия

Короткий вариант:

1. Войдите под Борисом.
2. Откройте объявление Анны и нажмите «Написать продавцу».
3. Отправьте сообщение.
4. Откройте [Mailpit](http://127.0.0.1:8025) и дождитесь письма Анне.
5. В отдельном браузерном профиле войдите под Анной и ответьте в разделе «Сообщения».

Две обычные вкладки одного профиля используют один вход. Для двух независимых пользователей нужен другой профиль браузера, другой браузер или обычное и приватное окно.

Подробный сценарий с созданием своего объявления: [инструкция для пользователя](user-guide.md).

## 7. Остановите и снова запустите стенд

```sh
make down
```

Команда останавливает контейнеры основного Compose-стенда и удаляет их. Данные остаются в Docker-томах — отдельных хранилищах, которые переживают удаление контейнера.

Вернуться к работе:

```sh
make up
```

Повторный `make seed` для уже созданных данных не нужен. Не удаляйте `.local/.env`: сохранённые базы и хранилище продолжают использовать прежние пароли.

Не добавляйте `-v` к команде `docker compose down`, если хотите сохранить данные. Этот флаг удаляет тома. Остановка программы и удаление её данных — разные действия.

Если вы отдельно подключили наблюдаемость, остановка всего стенда вместе с ней описана в [локальной разработке](../runbooks/local-development.md).

## Если запуск не получился

| Симптом | Что проверить сначала |
|---|---|
| `Cannot connect to the Docker daemon` | Запущен ли Docker Engine; повторите `docker version` |
| `port is already allocated` или `address already in use` | Порт занят другой программой; выясните какой, не завершайте чужие процессы наугад |
| Ошибка обязательной переменной окружения | Выполните `make setup`; используйте `--env-file .local/.env` в командах Compose |
| Ошибка скачивания образа или Go-зависимости | Проверьте интернет и доступ Docker к сети; затем повторите `make up` |
| Контейнер долго остаётся `unhealthy` | Посмотрите его логи, пример ниже |
| Страница открылась, но каталог пуст | Выполнен ли `make seed`; работают ли `search` и `kafka` |
| Демоаккаунт не входит после смены пароля в `.env` | Изменение файла не меняет пароль уже существующего аккаунта |
| Фотографии не видны | Работает ли `storage`, доступен ли порт 9000; не используете ли другой адрес сайта |

Посмотреть последние сообщения проблемного сервиса, например Search:

```sh
docker compose --env-file .local/.env logs --tail=80 search
```

Для первоначальной диагностики достаточно последних сообщений. Не вставляйте в публичное обсуждение файл `.local/.env`, токены или полный дамп базы.

Если причина неясна, переходите к [пошаговой диагностике](../runbooks/local-development.md). Там разобраны адреса сервисов, подключения к БД, наблюдаемость и пересборка изменённого кода.
