# Словарь без сложных формулировок

[К оглавлению](../README.md) · [Архитектура](../architecture/overview.md) · [Путеводитель по коду](code-tour.md)

Здесь собраны слова, которые встречаются в коде и документации. Объяснения относятся к этому проекту: реализация такого же понятия в другой системе может отличаться.

## Приложение и код

| Слово | Простое объяснение и пример |
| --- | --- |
| Сервис, микросервис | Отдельная программа с определённой работой. Listings отвечает за объявления, Messaging — за переписку |
| Gateway, шлюз | Вход в приложение для браузера. Отдаёт интерфейс и направляет API-запросы нужному сервису |
| API | Правила обращения к программе: какой адрес вызвать, что передать и какой ответ ожидать |
| HTTP | Протокол обмена запросами и ответами. Например, браузер просит сохранить объявление и ждёт результат |
| Endpoint, маршрут | Конкретная операция API: метод и путь, например `POST /api/v1/listings` |
| Handler, обработчик | Функция, которая принимает HTTP-запрос, выполняет действие и готовит ответ |
| Middleware, обёртка | Код вокруг обработчика: например, проверка токена перед выполнением запроса |
| Reverse proxy, обратный прокси | Посредник перед серверами. Gateway пересылает запрос в Listings и передаёт ответ обратно |
| JSON | Текстовый формат данных: объекты, массивы, строки и числа. Используется в HTTP и событиях |
| UUID | Уникальный идентификатор в виде строки. Так задаются ID пользователей, объявлений, диалогов и событий |
| Go module | Пакеты Go с общим именем и зависимостями, описанными в `go.mod`. В проекте модуль один, программ несколько |
| Пакет Go | Группа файлов одной папки с общим `package`. Например, файлы `services/listings` |
| Точка входа | Место начала программы — `func main()` в `cmd/<имя>/main.go` |
| Context | Объект Go для передачи отмены, срока операции и технических данных между функциями |
| Goroutine | Лёгкая параллельная задача внутри Go-процесса. Здесь так запускаются фоновые worker-ы |
| Worker | Фоновая задача: отправить outbox, обработать событие, отправить письмо или очистить фото |
| Конфигурация | Настройки программы: адрес БД, порт HTTP, ключи доступа. Код читает их из переменных окружения |
| Переменная окружения | Именованная настройка, переданная процессу, например `DATABASE_URL` |
| Контракт | Согласованные правила данных и поведения: поля запроса, события, ответа и возможные ошибки |

## Данные и поиск

| Слово | Простое объяснение и пример |
| --- | --- |
| PostgreSQL | Сервер базы данных: хранит таблицы, выполняет SQL и поддерживает транзакции |
| SQL | Язык работы с таблицами. `SELECT` читает, `INSERT` добавляет, `UPDATE` меняет, `DELETE` удаляет |
| Роль БД | Учётная запись подключения с правами. У каждого сервиса с БД своя роль |
| Владелец данных | Сервис, который определяет правила изменения оригинала. Для объявления это Listings, даже если Search хранит его копию |
| Транзакция | Несколько операций в одной БД, которые сохраняются вместе или отменяются вместе |
| Commit, фиксация | Сохранить результат транзакции. Не путайте с Git commit, который сохраняет версию исходников |
| Rollback, откат | Отменить изменения незавершённой транзакции |
| FOR UPDATE | SQL-блокировка выбранной строки до окончания транзакции, чтобы конкурирующие изменения не мешали друг другу |
| Advisory lock | Блокировка PostgreSQL, которую приложение берёт по выбранному ключу. Здесь выбирает одного активного отправителя outbox |
| Пул соединений | Набор открытых соединений с БД для повторного использования; в коде — `pgxpool.Pool` |
| Миграция | Пронумерованный шаг изменения структуры БД. Файлы `.up.sql` применяют изменение, `.down.sql` описывают обратный шаг |
| Индекс БД | Дополнительная структура, ускоряющая поиск строк. Это не отдельный сервис |
| Полнотекстовый поиск | Поиск по словам текста с языковой обработкой. Здесь PostgreSQL ищет в названии и описании объявления |
| GIN, tsvector | Средства PostgreSQL для полнотекстового поиска: индекс для быстрого поиска и подготовленное представление слов |
| Проекция | Копия данных, удобная для определённого чтения. Search хранит проекцию публичных объявлений |
| Snapshot, снимок | Состояние объекта на некоторую версию. Событие объявления несёт полное состояние публичных полей |
| Version, версия объекта | Число, увеличиваемое при изменении. Например, версия объявления `8` новее `7` |
| Expected version | Версия, которую клиент ожидает на сервере. Несовпадение даёт конфликт, защищая от перезаписи чужого более нового изменения |
| UPSERT | «Вставь новую строку, а при существующей — обнови». Search дополнительно обновляет только при более новой версии |
| Cursor, курсор | Значение, от которого читать следующую порцию списка. Для сообщений здесь это последний прочитанный `seq` |
| Пагинация | Разделение большого списка на порции. В каталоге используются страницы, в ряде других API — курсоры |
| Согласованность с задержкой | Оригинал уже изменился, копия ещё догоняет. Например, Listings сохранил новую цену, Search пока показывает старую |
| Reindex, переиндексация | Полная перестройка поисковой копии из экспорта Listings с учётом параллельных событий |
| S3, объектное хранилище | API хранения файлов по ключам. Здесь фотографии лежат в RustFS, совместимом с S3 |
| Bucket | Именованное хранилище объектов S3, здесь `photos` |
| Подписанная ссылка | Временный URL с разрешением прочитать конкретный файл; в проекте выдаётся на 15 минут |

## События и надёжность

| Слово | Простое объяснение и пример |
| --- | --- |
| Событие | Запись о том, что уже произошло: например, `message.created`, «сообщение создано» |
| Kafka, брокер | Система, которая принимает события, хранит их и позволяет другим программам читать их позже |
| Producer, отправитель | Код, записывающий события в Kafka |
| Consumer, потребитель | Код, читающий события из Kafka и выполняющий обработку |
| Topic, топик | Именованный поток записей: например, `marketplace.listings.v1` |
| Partition, партиция | Часть топика с собственным порядком записей. Общего порядка всех партиций нет |
| Key, ключ Kafka | Значение для выбора партиции. Здесь ID объявления или диалога |
| Consumer group, группа | Читатели, совместно обрабатывающие поток. У разных групп независимые позиции чтения |
| Offset | Позиция записи внутри партиции Kafka. Сохранённая позиция группы показывает, откуда ей продолжать |
| Commit offset | Подтверждение обработанной позиции Kafka. Это отдельное действие, не SQL-транзакция |
| Lag | Отставание группы от конца потока Kafka; помогает увидеть, успевает ли читатель обрабатывать изменения |
| Retention | Срок хранения записей. В локальной Kafka настроено семь дней, поэтому это не вечный архив |
| Реплика | Дополнительная копия данных на узле Kafka. Локально реплика одна, запасного узла нет |
| ISR | Реплики Kafka, считающиеся синхронизированными. Отправитель ждёт подтверждения всех текущих ISR |
| Envelope, конверт | Общие поля вокруг содержимого события: ID, тип, время, версия формата и версия объекта |
| Payload | Полезное содержимое внутри конверта. Например, снимок объявления |
| Aggregate | Объект, по которому нумеруются изменения и выбирается ключ. Здесь объявление или диалог |
| Schema version | Версия формата события. Это не номер изменения конкретного объявления |
| Outbox | Таблица «нужно отправить». Записывается вместе с бизнес-изменением, затем читается фоновым отправителем |
| Inbox | Таблица «это событие уже принято». В Notifications предотвращает создание второго задания с тем же `event_id` |
| Идемпотентность | Повтор операции даёт тот же результат, а не дополнительный объект. Например, повтор события не удваивает поисковую запись |
| Idempotency-Key | Ключ одного запроса отправки сообщения. В сочетании с диалогом и отправителем позволяет вернуть ранее сохранённое сообщение |
| At least once | «Как минимум один раз». Повторы доставки допустимы; получатель должен уметь их обрабатывать |
| Exactly once | «Строго один раз». Для внешней SMTP-отправки проект этого не гарантирует |
| Retry | Повтор неудачной операции: например, после временной недоступности БД |
| Backoff | Пауза между повторами, часто увеличивающаяся, чтобы не нагружать неисправную зависимость |
| DLQ | Отдельный топик для событий, которые нельзя обработать из-за их формата или данных. Нужен для разбора и последующего исправления |
| Replay | Повторное проигрывание событий. Команда `replay` в проекте повторно публикует выбранную запись из DLQ |
| Job, задание | Сохранённая в БД работа для будущего выполнения. Здесь — отправка письма |
| Lease, аренда | Временное право worker-а выполнять задание. После истечения срока работу может забрать другой worker |
| SKIP LOCKED | SQL-правило «пропусти уже заблокированные строки». Помогает worker-ам брать разные задания |
| SMTP | Протокол передачи писем почтовому серверу. Успешная отправка не доказывает прочтение адресатом |
| Mailpit | Локальный приёмник тестовых писем с веб-интерфейсом |

## Доступ и безопасность

| Слово | Простое объяснение и пример |
| --- | --- |
| Аутентификация | Проверить, кто обращается. Например, проверить JWT и получить ID пользователя |
| Авторизация | Проверить право выполнить действие. Например, убедиться, что объявление принадлежит этому пользователю |
| Хеш | Результат вычисления по значению. Пароли проверяются через bcrypt-хеш, refresh token хранится как SHA-256-хеш; это разные механизмы для разных задач |
| JWT | Подписанный токен с данными и сроком. Подпись защищает от подмены, но не делает содержимое секретным |
| Ed25519 | Алгоритм подписи. Accounts подписывает JWT закрытым ключом, сервисы проверяют открытым |
| Access token | Короткоживущий пропуск к API, здесь на 15 минут |
| Refresh token | Случайное значение для получения нового access token. Здесь связано с сессией в Accounts |
| Ротация | Замена использованного значения новым. Refresh token меняется при обновлении сессии |
| Cookie | Данные, которые браузер хранит и автоматически отправляет подходящему сайту |
| HttpOnly | Запрет JavaScript читать значение cookie. Так защищена cookie refresh token |
| SameSite | Правило, ограничивающее отправку cookie при обращениях с другого сайта. Здесь используется `Lax` |
| Origin | Адрес источника запроса: протокол, имя и порт. Проверяется при refresh и logout |
| HTTPS, TLS | Шифрование соединения и проверка стороны соединения. HTTPS — HTTP поверх TLS |
| SERVICE_TOKEN | Общий секрет внутренних HTTP-запросов сервисов. Сейчас он один и не различает вызывающий сервис |
| Allowlist | Явный список разрешённого. Gateway публикует только перечисленные публичные API-маршруты |
| Rate limit | Ограничение частоты запросов. Здесь действует по адресу соединения отдельно в каждом Gateway |
| SASL/PLAIN | Способ передать логин и пароль для аутентификации Kafka. Сам по себе не шифрует соединение; для этого нужен TLS |
| Секрет | Пароль, закрытый ключ или токен доступа. Такие значения не должны храниться в публичной истории Git |

## Запуск, проверки и наблюдаемость

| Слово | Простое объяснение и пример |
| --- | --- |
| Образ контейнера | Подготовленный набор программы и файлов для её запуска |
| Контейнер | Запущенная программа в изолированном окружении по образу |
| Docker Compose | Описание и совместный запуск нескольких контейнеров на одной машине |
| Том, volume | Постоянное хранилище Docker, сохраняющее данные после удаления контейнера |
| Kubernetes | Система запуска и управления контейнерами на узлах кластера |
| Pod | Единица запуска в Kubernetes: один или несколько тесно связанных контейнеров |
| Helm chart | Шаблоны и настройки установки приложения в Kubernetes |
| kind | Средство запустить учебный Kubernetes-кластер в Docker |
| Ingress | Входная HTTP-маршрутизация к приложениям Kubernetes; для работы нужен соответствующий контроллер |
| NetworkPolicy | Правила разрешённых сетевых соединений в Kubernetes; их должен поддерживать сетевой компонент кластера |
| CNI | Интерфейс и сетевые компоненты, которые подключают контейнеры Kubernetes к сети; поддержка NetworkPolicy зависит от выбранного компонента |
| Зависимость | То, без чего часть работы не выполнится: для Listings это, например, PostgreSQL и S3 |
| Liveness | Проверка, отвечает ли процесс. Не проверяет всю пользовательскую цепочку |
| Readiness | Проверка готовности принимать трафик. Здесь сервис с БД проверяет БД, но не успешность поиска или почты |
| Лог, slog | Запись о произошедшем; `log/slog` — библиотека Go. Здесь логи пишутся в stdout в JSON |
| Stdout | Стандартный поток вывода процесса; Docker собирает его и показывает в логах контейнера |
| Trace, трасса | Связанные участки одной операции в разных частях системы |
| Span | Один измеренный участок трассы, например HTTP-запрос или SQL-операция |
| Trace context | Идентификаторы и данные связи трассы, переносимые между HTTP, outbox и Kafka |
| Request ID | Идентификатор HTTP-запроса. Возвращается в `X-Request-ID`; не заменяет ID всей трассы |
| OpenTelemetry, OTel | Средства сбора и передачи технических наблюдений. Здесь используются для трассировки |
| Collector | Промежуточный приёмник телеметрии. В проекте принимает traces и передаёт в Jaeger; поток логов не настроен |
| Jaeger | Интерфейс просмотра трасс |
| Метрика | Числовой показатель, например длительность запросов или число ожидающих писем |
| Prometheus | Собирает и хранит метрики |
| Grafana | Показывает панели и графики по собранным данным |
| SLO | Численная цель качества сервиса: например, допустимая задержка. В проекте не следует путать её с обещанием или уже измеренным результатом |
| Unit-тест | Проверяет небольшой участок кода, например правило публикации |
| Интеграционный тест | Проверяет взаимодействие с зависимостями, например настоящей PostgreSQL или Kafka |
| Smoke-тест | Короткая проверка главного сценария через работающую систему |
| Build tag | Метка, определяющая, какие Go-файлы включать при запуске. Интеграционные тесты требуют своего `-tags` |
| Runbook | Практическая инструкция для оператора: как проверить, восстановить или обслужить систему |
